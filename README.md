# Kinox plus mobile
# KinoX Plus — Mobile App Technical Requirements  **Platform:** React Native **Companion to:** KinoX Plus web (Next.js) marketing site **Core product idea:** on-demand streaming fused with synced watch parties (playback sync + live video of friends' faces + reactions/chat)  ---  ## 1. Overview  KinoX Plus mobile is the consumer app where the actual product happens (the web app today is a marketing/waitlist site). The app needs to support:  1. Browsing a movie/show library 2. Creating or joining a "room" (watch party) 3. Millisecond-accurate synced video playback across every participant 4. Live video bubbles of participants' faces, layered over the video 5. Lightweight social — reactions, chat, invite links 6. Accounts, profiles, and a subscription tier ("Plus")  ---  ## 2. Tech Stack  | Layer | Choice | Why | |---|---|---| | Framework | **React Native (Expo, managed → prebuild/bare when needed)** | Fast iteration, OTA updates via EAS Update, easy camera/permissions/notifications setup. Design System  ### 3.1 Color palette  Reuse the exact tokens from [`src/app/globals.css`](../src/app/globals.css) so the app and the marketing site are visually identical. Define them once in `theme/colors.ts` and feed them into `tailwind.config.js` for NativeWind:  ```ts // theme/colors.ts export const colors = {   background: "#000000",   foreground: "#f2f3fa",    navy950: "#020308", // near-black card/surface   navy900: "#070a24",   navy800: "#0d1435",    // Gulf Blue — primary accent (CTAs, active states, brand mark)   blue600: "#0c38a4",   // Torea Bay — deepest accent (pressed/hover, headers)   blue700: "#080e5a",    blue500: "#1f4bc4",   blue400: "#4a72d6",   blue300: "#8aa3e8",   blue200: "#bccdf3",   blue100: "#e2e9fb", } as const; ```  Usage convention: - **`background` (#000000)** — every screen root. The app should read as *very black*, matching the web redesign — no default light-gray RN backgrounds anywhere. - **`navy950/900/800`** — elevated surfaces (cards, sheets, modals, tab bar, input fields), darkest → least elevated. - **`blue600` (Gulf Blue)** — primary buttons, active tab icon, links, focus rings, logo mark. - **`blue700` (Torea Bay)** — pressed/hover states, header gradients behind video, active room indicator. - **`blue100–400`** — body copy on dark surfaces, secondary text, muted labels (mirrors `text-blue-100/60` etc. utility patterns from web).  ### 3.2 Typography  - **Font: Helvetica Neue**, matching `--font-helvetica` on web. - iOS ships Helvetica Neue natively — no bundling needed, reference by family name. - Android has **no system Helvetica Neue** and it isn't freely licensed for redistribution. Two options:   1. License the font files (Helvetica Neue via Linotype/Monotype) and bundle via `expo-font` (`useFonts` hook), same weights used on web (Regular, Medium, Bold).   2. If licensing isn't available, fall back to **Inter** or **SF Pro-adjacent** system fonts on Android only, keeping Helvetica Neue on iOS — configure per-platform in the NativeWind font config so this stays a one-line decision, not scattered `Platform.select` calls. - Type scale should mirror the web's `text-4xl/6xl/7xl` hero, `text-3xl/4xl` section headings, `text-sm/base` body — define as RN `fontSize`/`lineHeight` tokens in `theme/typography.ts`.  ### 3.3 Shared component primitives  Port the same small set of primitives already on web (`Button`, `GlowCard`, `SectionHeading`, `Reveal`) to RN equivalents so both codebases share vocabulary: - `Button` — solid (Gulf Blue) / secondary (outline, white/10 border) / sizes sm/lg, same as `src/components/ui/Button.tsx`. - `Card` (RN version of `GlowCard`) — `navy-950` background, `border-white/10`, subtle glow on focus/press instead of hover. - `SectionHeading`, `Reveal` (as a Moti fade/slide-in wrapper), `Avatar`, `Badge`, `EmptyState`.  ---  ## 4. Screens  ### 5.1 Splash & Launch - **Splash Screen** — logo mark on pure black, matches web favicon/logo treatment. - **Auth check / bootstrap** — silent screen that reads MMKV session token, routes to Onboarding, Auth, or Home.  ### 5.2 Marketing Onboarding (pre-auth, first install only) - **Onboarding Carousel** (3 slides) — "Movies are better together," "Synced playback, zero drift," "See your friends' faces, not just their names" — mirrors Hero/FeatureShowcase copy from web. Skippable, shown once (persisted flag in MMKV).  ### 5.3 Authentication - **Sign Up** — email + password, or continue with Apple/Google. - **Log In** - **Forgot Password** - **OTP / Email Verification** — 6-digit code input. - **Reset Password**  ### 5.4 Account Setup Onboarding (post-signup, pre-Home) Required screens, in order: 1. **Welcome** — personalized "Hey, let's set up your room" screen. 2. **Choose Your Categories** — grid/chip multi-select of movie genres (Action, Comedy, Horror, Romance, Sci-Fi, Documentary, Anime, Family, etc.) — minimum 3 selections required to personalize the home feed's recommendation rail. 3. **Create Your Profile** — username (with live availability check), display name, avatar (upload or pick from a preset set of avatar illustrations), optional short bio. 4. **Permissions Priming** — explain *why* camera/mic access is needed ("so your friends can see you in the room") before triggering the native OS prompt, then request camera + microphone + notifications permissions. 5. **Onboarding Complete / Confetti** — transitions into Home.  ### 5.5 Home (Tab) - **Home Feed** — "Continue Watching" rail, "Because you like [category]" rails, "Trending in watch parties" rail, curated hero banner. - **Active Room Banner** — persistent sticky card if the user currently has a live room ("Your room is live — 3 friends watching"), tap to rejoin.  ### 5.6 Discover / Search (Tab) - **Search Screen** — search bar + recent searches + trending queries. - **Category Browse** — grid of titles filtered by the genres chosen in onboarding, with a filter/sort sheet. - **Search Results**  ### 5.7 Title Details - **Movie/Show Detail Screen** — poster, synopsis, cast, runtime, "Start a Room" primary CTA, "Add to Watchlist" secondary, episode list if a series.  ### 5.8 Rooms (the core feature) - **Create Room** — pick a title (or "decide later"), name the room, privacy toggle (invite-only by default per the "private by default" value on web), generate invite link/QR. - **Invite Sheet** — shareable link, QR code, "invite from contacts," copy link. - **Room Lobby** (pre-play, while friends join) — participant avatars joining in real time, mic/camera preview tiles, "Start Playback" (host only). - **Watch Party Room (Player Screen)** — the flagship screen:   - Full-bleed video player with custom controls (play/pause, scrub bar disabled for guests, volume, fullscreen, closed captions, playback quality).   - Floating **face bubbles** (LiveKit video tiles) for each participant, draggable/resizable, tap to mute/pin.   - **Reactions bar** — emoji burst overlay (❤️ 😂 😱 👏) matching the web's playful tone.   - **Sync status indicator** — subtle "synced" pill; if drift is corrected, briefly show "syncing…".   - **Room chat drawer** — swipe-up text chat, in case a participant has camera/mic off.   - **Participant list / room settings sheet** — mute all, remove participant (host only), leave room, end room (host only). - **Join Room (via deep link)** — invite-link landing → auth check → lobby. - **Room Ended / Recap Screen** — "You watched [Title] with 3 friends for 1h42m," rate the movie, start another room.  ### 5.9 Profile (Tab) - **Profile Screen** — avatar, username, bio, watch stats (rooms hosted, hours watched), watchlist shortcut, edit-profile CTA. - **Edit Profile** — same fields as onboarding step 3. - **Watchlist** - **Watch History** - **Friends / Following** — list, add-friend via username or invite link.  ### 5.10 Settings - **Settings Home** — account, notifications, playback quality/data usage, privacy (who can invite me to rooms), app appearance (dark only, per brand direction — no light mode toggle needed but keep the screen extensible), about/legal, log out. - **Notification Preferences** - **Subscription / Plans ("Plus")** — plan comparison, current plan, manage/cancel, payment method (via RevenueCat or Stripe). - **Help & Support** — FAQ (reuse copy from `src/lib/data.ts` `faqs`), contact support form (mirrors web `ContactForm`/`ContactInfo`). - **Privacy Policy / Terms** — web view or bundled markdown.  ### 5.11 Notifications (Tab or bell icon) - **Notifications Feed** — "X started a room," "Y invited you," "Your room starts in 10 min," system announcements.  ### 5.12 Cross-cutting / system screens - **Empty States** — empty watchlist, no search results, no active rooms. - **Error States** — network error, room full, room ended, permission denied (camera/mic) with a "open settings" CTA. - **Offline Banner** - **Force Update Screen** — if app version is below the minimum supported version. - **Paywall / Upgrade Sheet** — triggered when a free-tier limit is hit (e.g., room size cap).  ---  ## 6. Navigation Map (high level)  ``` RootNavigator ├── (unauthenticated) │   ├── OnboardingCarousel │   └── AuthNavigator (SignUp, Login, ForgotPassword, VerifyOtp) ├── (authenticated, profile incomplete) │   └── AccountSetupNavigator (Welcome, Categories, CreateProfile, Permissions, Complete) └── (authenticated, profile complete)     └── AppTabs         ├── HomeStack (Home, TitleDetails)         ├── DiscoverStack (Search, CategoryBrowse, TitleDetails)         ├── RoomsStack (CreateRoom, Lobby, Player, Recap)  — also reachable via deep link outside tabs         ├── NotificationsStack         └── ProfileStack (Profile, EditProfile, Watchlist, History, Friends, Settings*, Subscription) ``` `Player` presents as a full-screen modal from anywhere (tab bar hidden), since a user can be deep-linked straight into a room without going through tabs.  ---  ## 7. Non-functional requirements  - **Sync accuracy:** server-authoritative clock, client playback rate nudged within ±0.05x rather than seeking, target <150ms perceived drift. - **Low-latency video:** LiveKit/Agora SFU tuned for sub-500ms glass-to-glass for face bubbles. - **Cold start:** under 2s to splash-to-interactive on a mid-tier Android device. - **Accessibility:** Dynamic Type / font scaling support, VoiceOver/TalkBack labels on all interactive controls (especially player controls and reaction buttons), minimum 44×44pt tap targets. - **Offline handling:** cached "Continue Watching" and watchlist metadata via React Query persistence; rooms/live features require connectivity and should show a clear offline state rather than failing silently. - **Security:** JWT short-lived access token + refresh token in MMKV encrypted storage; invite links carry a signed, expiring token, not a raw room ID. - **Privacy:** camera/mic permission requests are always paired with in-app context (never a bare OS prompt), matching the onboarding step 4 design.
